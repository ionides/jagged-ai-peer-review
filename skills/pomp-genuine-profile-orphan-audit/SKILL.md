# POMP Genuine Profile Orphan Audit

## Purpose

A POMP project may run a genuine profile likelihood search (with `profile_design()` and a dedicated `mif2()` loop that fixes the target parameter) in a separate script or cluster job, saving the result as a named RDS or CSV file. If the Rmd is then written or edited without loading this genuine profile artifact, but instead constructs a pseudo-profile by filtering and grouping global-search results, the following compound failure occurs:

1. The analysis displays a statistically invalid pseudo-profile with chi-squared CI cutoffs that have no valid interpretation.
2. The better, correctly computed profile results are silently discarded.
3. The genuine profile may also reveal that the global search missed the true MLE (because the genuine profile, by fixing the target parameter at a grid of values and optimizing all other parameters freely, can explore regions that the box-constrained global search never reached).

This error is distinct from:
- `pomp-pseudo-profile-audit`: that skill handles cases where no genuine profile search was ever run. Here, a genuine profile search was run and its artifact exists — it is simply not used in the Rmd.
- `pomp-artifact-audit`: that skill checks for inconsistencies between loaded artifacts and source code. Here, the artifact is not loaded at all, so there is no inconsistency to check — the problem is omission.
- `pomp-profile-pre-global-seed-error`: that skill handles cases where a genuine profile is run but seeded from the wrong CSV state. Here, the genuine profile exists but is entirely absent from the Rmd.

## When to Activate

Use this skill when:
- A POMP project has a file in the project folder whose name suggests it is a profile result (e.g., `profile_rho.rds`, `writeup_profile_rho.rds`, `profile_sigma.csv`, `profile_results.rds`).
- The Rmd source contains no `readRDS()` or `read_csv()` call that loads this file.
- The Rmd does contain a parameter-vs-loglik plot described as a "profile" or used to derive a confidence interval, but that plot is constructed from global-search or local-search data instead.

Do not use this skill when:
- The Rmd does load the profile artifact (even if under a different variable name).
- The profile-named file is empty, corrupt, or was generated by a different analysis in the same folder.
- The project runs the profile search inline using `bake()` inside the Rmd, so no pre-computed artifact is needed.

## Procedure

### 1. Scan the project folder for profile artifacts

List all RDS and CSV files in the project directory. Flag files whose names contain "profile" or related terms (e.g., `profile_rho`, `profile_lik`, `if_profile`).

### 2. Scan the Rmd source for references to each flagged artifact

Search for `readRDS`, `read_csv`, `read.csv`, `load()`, or `bake()` calls that reference the flagged filename. If no such call is present, the artifact is orphaned.

### 3. Identify the profile code in the Rmd

Locate the code that produces the parameter-vs-loglik plot labeled as a "profile" or used for a confidence interval. Determine what data object is being plotted:
- If it is the global search result object (e.g., `writeup_params.csv`), the profile is a pseudo-profile (see `pomp-pseudo-profile-audit`).
- If it is a separate profile-specific object loaded via `profile_design()` or a dedicated profile RDS, the profile may be genuine.

### 4. Compare log-likelihoods between the orphaned artifact and the global search

Load both the orphaned profile artifact and the global search result file. Compare:
```r
max(profile_artifact$loglik, na.rm=TRUE)   # genuine profile best
max(global_search$loglik, na.rm=TRUE)      # global search best
```
If the genuine profile achieves a higher log-likelihood than the global search by more than ~3 units (accounting for Monte Carlo noise), this confirms:
- The genuine profile found a region of parameter space that the global search missed.
- The global search box was misaligned or the search was inadequate.
- The pseudo-profile presented in the Rmd was constructed from an inferior parameter set.

### 5. Assess the impact on the reported CI

Determine the CI reported in the Rmd (from the pseudo-profile). Compare it to what the genuine profile would produce using the correct global MLE as the reference:
```r
cutoff <- max(global_search$loglik) - 0.5 * qchisq(df=1, p=0.95)
valid_ci <- profile_artifact[profile_artifact$loglik > cutoff, target_param]
range(valid_ci)
```
Report the discrepancy between the reported CI (from pseudo-profile) and the valid CI (from genuine profile using correct reference).

### 6. Report the finding

For each detected instance, report:
- The name of the orphaned profile artifact and the project folder.
- The absence of any `readRDS` / `read_csv` call for it in the Rmd.
- The code location in the Rmd where the pseudo-profile is constructed.
- The log-likelihood gap between the genuine profile and the global search (if positive, this indicates global search inadequacy).
- The consequence: the analysis presents an invalid pseudo-profile CI while ignoring a better-computed genuine profile; all stated confidence intervals for the profiled parameter are unreliable.
- The fix: load the genuine profile artifact in the Rmd, apply the chi-squared CI cutoff referenced to the global maximum log-likelihood (or the profile maximum if it is higher, which would indicate the global search was inadequate and should be re-run), and remove the pseudo-profile code.

## Limitations

- This skill requires access to both the project folder contents (to detect orphaned artifacts) and the Rmd source (to confirm the artifact is not loaded). It cannot be applied from the HTML output alone.
- A profile artifact may be genuinely stale (e.g., generated from an earlier model version before the analysis was revised). If the artifact parameters are inconsistent with the current model's `paramnames`, flag this inconsistency but do not conclude the profile is valid for the current model.
- The log-likelihood comparison in Step 4 requires that both artifacts are computed under the same model and dataset. If the profile was run on a different data subset or model variant, the comparison is invalid.
- Does not replace `pomp-pseudo-profile-audit`, which should also be applied to characterize the specific failure mode of the displayed pseudo-profile.
