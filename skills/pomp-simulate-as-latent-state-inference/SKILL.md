# POMP Simulate-as-Latent-State Inference Detector

## Purpose

A correct reconstruction of latent state trajectories in a POMP model requires conditioning on the observed data, which is achieved by running the particle filter (`pfilter()`) and extracting the empirical distribution of state particles at each observation time. A common student error is to call `simulate()` with the fitted parameter vector and plot the resulting state trajectory as if it were the inferred latent state sequence. Because `simulate()` draws unconditionally from the model's prior process distribution (given the parameters), the resulting trajectory is statistically independent of the observed data — it tells us nothing about what the latent state *was* during the observation period. Labeling this as "inferred" or "reconstructed" is factually incorrect and misleads readers about what has been learned from the data.

This error is visually indistinguishable from a correct filtering-distribution plot in the rendered output, because both show a time series of state values. The error can only be detected by reading the source code.

## When to Activate

Use this skill when:
- A POMP project plots a latent state variable over time (e.g., a regime indicator sequence, a latent volatility path, a latent susceptibility level).
- The plot is labeled "Inferred [State] Over Time," "Reconstructed [State]," "Estimated Latent Trajectory," or similar language implying conditioning on data.
- The code generating the plot calls `simulate()` on a fitted pomp object rather than extracting state particles from `pfilter()`.

Do not use this skill when:
- The project explicitly labels the plot as a "simulated" or "forward-simulated" trajectory and does not claim it reflects conditioning on data.
- The project uses `pfilter()` and extracts state summaries (e.g., via `filter_mean()`, `filter_traj()`, or by directly reading the `$filter.mean` slot from a pfilter result) to construct the plot.
- The project uses a smoothing method (e.g., particle smoothing via `bsmc2()` or PMCMC trajectory draws) that correctly conditions on all observations.

## Procedure

### 1. Locate the latent state plot

Search the Rmd/R source for code that produces a time-series plot of a latent state variable. Identify the plot label or title.

### 2. Identify the data source for the plot

Trace the data object used in the plot back to its creation:
- **Error pattern**: The plot data comes from `simulate(pomp_object, params = coef(fitted_mif), nsim = K, ...)` — this generates trajectories from the prior process distribution given estimated parameters, without conditioning on observations.
- **Correct patterns**:
  - `pfilter(pomp_object, params = coef(fitted_mif), Np = K)` followed by extraction of `filter_mean(pfilter_result)` or the `$filter.mean` slot.
  - `bsmc2()` or PMCMC draws of state trajectories from the posterior.
  - Viterbi decoding or forward-backward algorithm applied to the particle filter output.

### 3. Assess whether the plot label claims conditioning on data

Read the surrounding narrative. If the text uses language like "inferred," "reconstructed," "estimated from data," or "conditioning on observed returns" for a plot generated by `simulate()`, flag the mismatch as a major error.

### 4. Assess the impact on conclusions

If the latent state plot is used to:
- Identify which time periods are in high vs. low volatility regimes — these periods reflect random draws, not data-driven inference.
- Validate that the model captures known structural breaks or market events — the correspondence is coincidental.
- Support parameter interpretation (e.g., "Regime 2 dominates during period X, consistent with the 2023 market stress") — this inference is invalid.

Flag all such conclusions as unsupported.

### 5. Propose the fix

Describe the correct approach:
1. Run `pf <- pfilter(fitted_pomp, params = coef(mif_result), Np = K)` with a large K (e.g., 5000).
2. Extract the filtering mean of the latent state: for continuous states, use `filter_mean(pf)["state_name", ]`; for discrete states (e.g., regime), compute the particle-weighted fraction in each regime at each time point by examining the particle ensemble.
3. For discrete latent states with only 2–3 values, a simple summary is the fraction of particles in each state at each observation time: `apply(pf@filter.traj["regime",,], 2, function(x) mean(x == 1))`.
4. Plot the resulting time series as the "estimated probability of regime 1" or "filtering mean of latent volatility," not as a single realized path.

## Limitations

- This skill detects the error from code structure alone; the rendered plot may look identical whether `simulate()` or `pfilter()` was used.
- For models with a very informative likelihood (e.g., the data tightly constrain the latent state), a forward simulation from the estimated parameters may visually resemble the filtering distribution — but this is coincidental and the error should still be flagged.
- For continuous latent states (e.g., Heston volatility), extracting the filtering distribution requires inspecting the particle ensemble at each time step, which is more involved than for discrete states. In many `pomp` versions, `filter_mean()` directly returns the empirical mean of the filtering distribution for each state variable.
- Does not replace the broader model diagnostics audit (Wheeler et al. 2024, §4); this skill focuses specifically on the simulate-vs-filter confusion for latent state visualization.
