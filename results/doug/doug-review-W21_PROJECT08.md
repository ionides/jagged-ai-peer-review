# Peer Review: Statistical Models for Solar Flare X-ray Flux Time Series
**Reviewer:** Doug  
**Project:** W21 Project 08  
**Date:** 2026-04-10

---

## Summary

This project applies a progression of time-series models to solar X-ray flux data from 2019 (718 half-day observations in log scale), comparing ARMA, GARCH, several binary Hidden Markov Models, and a Heston stochastic volatility model via POMP. The authors make a genuine contribution by applying HMM and stochastic-volatility frameworks to solar flare data and demonstrating that the Heston model achieves the best log-likelihood (-21.66) and AIC among all candidates. While the modeling is creative and the POMP implementation is largely competent, the paper has significant methodological weaknesses: (1) the global search for the Student-t HMM and the Heston model both inherit the problematic anti-pattern of passing a prior `mif2` result as the first argument to `mif2()`, anchoring the global search near the local optimum; (2) the "profile CIs" for both the Gaussian and Student-t HMM models are not true profile likelihoods — they are filtered global-search scatter plots with no constrained optimization — and the chi-squared CI cutoffs applied to them are statistically invalid; (3) the Gaussian HMM AR(1) model runs the initial particle filter on a simulated object rather than the real data; (4) the Heston model global search box contains a parameter (`sigma_nu`) not present in the model's `paramnames`, creating a silent mismatch; and (5) no non-mechanistic benchmark comparison is performed to quantify what interpretive value the mechanistic models add.

## Major Issues

### 1. Global Search Anti-Pattern: Prior mif2 Result Passed as First Argument to mif2

In both the Student-t HMM (lines around chunk `Global Optimization Search`, offset ~792) and the Heston model (offset ~1585), the global search uses `mif2(if1[[1]], params=...)` — passing the first local-search `mif2` result object (`if1[[1]]`) as the initial object rather than the base `pomp` object. This is the anti-pattern documented in the `pomp-global-search-init-audit` skill: the global search replicates inherit the cooling schedule from `if1[[1]]`, which is already at or near its final cooled state after `Nmif` iterations. The newly sampled box parameters are applied but effectively explored only with near-zero IF2 perturbations. The "global maximum" may therefore not be meaningfully different from the local-search solution. The Gaussian HMM AR(1) section exhibits the same pattern at offset ~1213 (`mif2(if1[[1]], params=...)`).

**Fix:** Replace `mif2(if1[[1]], params=...)` with `mif2(hmm.filt, params=...)` (or the appropriate base `pomp` object) in the global search loop, so that each replicate begins from a fresh, fully cooled-schedule starting point.

### 2. Pseudo-Profile Likelihoods: No Constrained IF2 Optimization Was Run

For both the Gaussian HMM (Section 5) and the Student-t HMM (Section 6), the "poor man profile CI" is constructed by:

```r
read_csv("hmm_params.csv") %>%
  filter(loglik > max(loglik) - 50) %>%
  group_by(round(mu0, 5)) %>%
  filter(rank(-loglik) < 3) %>% ...
  ggplot(aes(x=mu0, y=loglik)) + geom_smooth(...) +
  geom_hline(yintercept = ci.cutoff)
```

There is no `profile_design()` call, no `foreach` loop with the target parameter fixed in the IF2 call, and no `rw.sd` that sets the profiled parameter to zero. This is a scatter plot of the global-search results filtered and grouped by the profiled parameter. The chi-squared cutoff (`max(loglik) - 0.5 * qchisq(df=1, p=0.95)`) is then applied to this scatter to read off confidence intervals. Per the `pomp-pseudo-profile-audit` skill, this procedure has no valid statistical interpretation as a profile likelihood: the optimization at each parameter value was not constrained to hold the target parameter fixed, so the resulting curve is not the profile. The stated CIs for `mu0`, `mu1`, `p0`, `p1` and their counterparts in the t-HMM section are unreliable.

**Fix:** Construct genuine profile likelihoods using `profile_design(mu0, lower=..., upper=..., nprof=K)`, run a new IF2 optimization at each grid value with `mu0` excluded from `rw.sd`, and evaluate the log-likelihood at each profile result. Apply the chi-squared cutoff to the resulting profile curve.

### 3. Initial Particle Filter for AR-HMM Evaluated on Simulated Data, Not Real Data

In the Gaussian HMM AR(1) section (offset ~1127–1133), the initial particle filter evaluation is:

```r
pf1 <- foreach(i=1:Nreps_eval, .packages='pomp') %dopar% 
  pfilter(sim1.filt, Np=Np, params=c(params, fixed_params))
```

`sim1.filt` is a `pomp` object constructed from a simulated dataset (`sim1.sim` generated by `simulate(hmm.sim, seed=1, ...)`), not from the real `data_ts`. The reported `L.pf1` is the log-likelihood on simulated data and is not comparable to the IF2 likelihoods that are computed on the real data. This matches the `pomp-simdata-benchmark-error` pattern. The text does not acknowledge that the initial particle filter run uses a different dataset from all subsequent computations.

**Fix:** Evaluate the initial particle filter on `hmm.filt` (the real-data pomp object) rather than `sim1.filt`, and label the value as a starting-point check on real data.

### 4. Heston Global Search Box Contains an Undeclared Parameter (`sigma_nu`)

In the Heston model global search (offset ~1569–1580), the search box is:

```r
heston_box <- rbind(
  sigma_nu = c(0.005, 0.05),
  k = c(0.01, 0.6),
  s_bar = c(0.01, 0.5),
  ...
)
```

The parameter `sigma_nu` is present in the box but does not appear in `heston_paramnames` (which lists `k`, `s_bar`, `s`, `l`, `m_bar`, `e`, `rho`, `M0`, `Z0`). When `apply(heston_box, 1, function(x) runif(1, x[1], x[2]))` generates a starting parameter vector, it will include `sigma_nu` as an extra named element not expected by `pomp`. In R, `mif2()` will either silently ignore the extra element or fail depending on version behavior. More importantly, every starting-parameter vector has one extra element, meaning the parameter counts are inconsistent. This is a direct parameter-name mismatch between the box and the model specification, which could affect whether the global search reliably covers the intended parameter space.

**Fix:** Remove `sigma_nu` from `heston_box` (it appears to be a leftover from a different model version), or add it to `heston_paramnames` if it is genuinely part of the model.

### 5. No Non-Mechanistic Benchmark Comparison

The paper does not compare any POMP model against a simple non-mechanistic benchmark (e.g., an ARMA model evaluated on the same data and scale, or an auto-regressive Gaussian baseline) using a common likelihood scale. The ARMA(1,3) in Section 4 uses the standard Gaussian ARMA likelihood (from `arima()`), while the POMP models use particle-filter likelihoods under different measurement models (Gaussian HMM, Student-t HMM, Gaussian AR(1) with covariate, and Heston). Because the observation models differ, the log-likelihood values are not directly comparable across families. The conclusion that the Heston model is the "best" model based on the highest log-likelihood is valid only within the POMP-family models that share a comparable observation model structure. Without a common-scale benchmark comparison (e.g., both ARMA and Heston evaluated under the same measurement model and data representation), it is unclear how much of the Heston model's apparent superiority stems from the richer process model versus the measurement model or number of parameters. See Wheeler et al. (2024), Section on benchmark comparisons.

**Fix:** Evaluate a simple non-mechanistic benchmark (e.g., a Gaussian AR(1) on the log-scale data) under the same measurement model used by the HMM models, and compare log-likelihoods on the same scale. Alternatively, compare AIC values carefully accounting for the different observation models.

### 6. Inadequate Computational Effort for Heston Model (Low Particle Count)

For the Heston model, `run_level=3` sets `Np=2e3` (2,000 particles). For a 9-dimensional continuous-state POMP model with strong autocorrelation in the latent volatility and mean processes, 2,000 particles is likely insufficient to control Monte Carlo variance in the particle filter likelihood. The standard error of the log-likelihood estimate is not reported alongside the Heston MLE. If the SE is large (e.g., > 1 log-unit), the reported best log-likelihood of -21.66 may be a noisy upward fluctuation rather than the true MLE. The paper reports the MLE but does not acknowledge this uncertainty.

**Fix:** Report the SE of the particle filter log-likelihood at the reported MLE, obtained via `logmeanexp(..., se=TRUE)`. Consider increasing `Np` to 5,000–10,000 for the Heston model given its higher dimensionality.

### 7. Gaussian HMM AR(1) Model Is Acknowledged to Be Misspecified But No Resolution Is Provided

The paper explicitly observes at multiple points (offsets ~1107, ~1195) that the log-likelihood for the AR-HMM increases then decreases as IF2 iterations proceed — a classical signature of model misspecification. The authors acknowledge this is "puzzling" and defer resolution to "future work," but still present the final parameter estimates and compare the model's best log-likelihood to those of other models in the conclusion table. Using a model that is known to be misspecified (by the authors' own diagnosis) in a formal model comparison is problematic: the reported log-likelihood is not a valid MLE and the comparison is misleading.

**Fix:** Either (a) exclude the AR-HMM from the formal model comparison table and report it only as an exploratory analysis with a known pathology, or (b) investigate the source of misspecification (e.g., parameter confounding between `a_k` and `b_k`, visible in the positive linear relationship noted at offset ~1195) and resolve it before reporting.

### 8. Model Comparison Table Mixes Incompatible Log-Likelihoods

The final comparison table (offset ~1701–1724) places ARMA(1,3) log-likelihood (Gaussian ARMA), GARCH(1,1) log-likelihood (GARCH on de-meaned data), ARMA+GARCH log-likelihood, Gaussian HMM (POMP, Gaussian measurement), Student-t HMM (POMP, t-distribution measurement), and Heston model (POMP, Gaussian on SDE state) in a single column with identical formatting. Because these models use different observation models, different data transformations (GARCH is on de-meaned data), and different likelihood definitions, the numbers are not directly comparable as goodness-of-fit measures for the same question. The paper does not acknowledge this limitation. The AIC values have similar issues because AIC = -2LL + 2k assumes the log-likelihoods are on a common scale.

**Fix:** Add a column to the table noting the observation model for each row, and include a footnote clarifying that log-likelihoods across different observation model families are not directly comparable. Restrict formal model selection (e.g., the claim that Heston is "best") to models sharing the same observation model.

### 9. Pairs Plot Error in Gaussian HMM Code

In the Gaussian HMM local search section (offset ~386), the pairs plot is:

```r
pairs(~loglik+mu0+mu1+sigma0+sigma1+p0+01, data=results, pch=16)
```

The column name `01` is clearly a typo for `p1`. In R this would either fail or display a column named `01` (which does not exist in `results`), silently dropping the p1 dimension. This is a minor code error but affects the diagnostic usefulness of the pairs plot.

**Fix:** Replace `01` with `p1` in the pairs plot call.

## Minor Issues

- **Parameter `eta` missing from partrans for t-HMM**: The Gaussian HMM declares `logit=c("p0","p1")` in `partrans` but `eta` (the initial-state probability, which is in (0,1)) does not receive a `logit` transform in the t-HMM pomp construction (offset ~646). It is declared in `paramnames` but receives only a log transform for `s0` and `s1`. If eta is intended to be constrained to (0,1), it should be declared with `logit` in `partrans` for consistency.

- **Only a single simulation used for MLE validation in t-HMM and Heston**: At the MLE, both the Student-t HMM (offset ~862) and the Heston model (offset ~1669) simulate only `nsim=1` trajectory and compare it to data. A single simulation is highly variable; showing 3–10 simulations would give a better visual assessment of the model's ability to reproduce key data features.

- **"Last iteration estimator" for AR-HMM lacks formal statistical justification**: The paper introduces the "last iteration estimator" (offset ~1249) as the best parameters at the final IF2 iteration rather than the likelihood-maximizing parameters. While this is a reasonable heuristic when the likelihood trace is non-monotone, it is not a standard statistical estimator and the paper does not discuss its properties or when it may fail.

- **No model diagnostics beyond visual simulation**: The paper relies entirely on visual comparison of simulated vs. observed trajectories for model adequacy. Conditional log-likelihood plots and ESS traces are computed for the t-HMM (offset ~827–836) and Heston model but not interpreted or used to identify periods of model failure. Per Wheeler et al. (2024), conditional log-likelihoods are the primary tool for identifying where a model fails — they should be shown and discussed.

- **Data aggregation choice not validated**: The raw 1-minute GOES data is aggregated to 12-hour windows using the 97.5th percentile. This choice is not compared to alternatives (e.g., maximum, median), and its effect on the estimated dynamics and model comparison is not assessed. A brief sensitivity check would strengthen this preprocessing decision.

- **Missing `sessionInfo()` and package versions**: The document does not include any record of R or package versions. Given that the `pomp` package API has changed across versions, exact reproduction of results requires version pinning (e.g., via `renv`). The current submission would be difficult to reproduce on future R/pomp versions.

- **Heston model Euler discretization has a non-standard log-volatility parameterization**: The discretized update for variance in the rprocess (offset ~1365) uses `exp(-Z)` inside the mean-reversion term: `k*(exp(-Z)*s_bar - 1)`. This is not the standard Euler-Maruyama discretization of the Heston SDE (which would use `V = exp(Z)` and update `dZ` based on Ito's lemma). The justification for this reparameterization is not provided, and the resulting dynamics may not correspond to the stated Heston model. This should be verified and derived explicitly.
